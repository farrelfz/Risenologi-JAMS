# RFC-0001: Request for Comments Template

## Purpose
Provide the standard template for proposing significant product, architecture, operational, or governance changes before implementation.

## Scope
Applies to proposals that require stakeholder discussion, alternatives analysis, approval, phased rollout, or documentation before implementation work begins.

## 2. Problem Statement
Describe the problem, opportunity, or governance gap this proposal addresses.

The problem statement SHALL explain who is affected, why the issue matters, and what happens if no action is taken.

## 3. Goals
List measurable outcomes the proposal is intended to achieve.

## 4. Non-Goals
List explicit boundaries. Non-goals SHALL prevent accidental expansion of product, architecture, data, API, UI, or operational scope.

## 5. Proposal
Describe the proposed change at the appropriate level of detail.

The proposal SHALL avoid implementation code unless the RFC explicitly concerns code-level standards. It SHOULD describe decisions, rationale, trade-offs, and review needs.

## 6. User and Stakeholder Impact
Identify affected user groups, business stakeholders, operational roles, and maintainers.

## 7. Security and Privacy Considerations
Describe authentication, authorization, data protection, auditability, abuse prevention, privacy, and compliance implications.

If there is no security or privacy impact, the RFC SHALL state why.

## 8. Operational Considerations
Describe effects on support, monitoring, observability, deployment, rollback, documentation, training, and maintenance.
